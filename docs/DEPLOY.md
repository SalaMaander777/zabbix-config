# Развёртывание Zabbix на объекте без интернета: полная инструкция

Документ для человека, который ставит систему на объекте. Распечатайте его или сохраните на флешку: на объекте интернета нет, ссылки из документа там не откроются.

Подробности по отдельным темам: `HYPERV-VM.md` (виртуальная машина), `CISCO.md`, `INFINET.md`, `ESMD.md`, `MAPS.md`, `RUNBOOK.md`, `DECISIONS.md` (решения и открытые вопросы).

---

## 1. Как это работает

### 1.1. Состав

```
 Рабочие места (браузер)                    Оборудование в сети
 Win 7/10/11                                Cisco 1921, 2901     ── SNMPv3 ──┐
   │  http://<IP>/       веб-интерфейс      Infinet R5000        ── SNMP ────┤
   │  http://<IP>:8081/  карта + Excel      R&S ESMD, EB500      ── ICMP, TCP 5555, SCPI ─┤
   ▼                                        ПК Windows (агенты)  ── TCP 10050/10051 ───┤
┌──────────────────────── СЕРВЕР ZABBIX ─────────────────────────────────────┐       │
│  zabbix-web     (nginx + PHP)  : 80    веб-интерфейс, API                    │       │
│  zabbix-server                 : 10051 опрос устройств, триггеры  ◄──────────┘
│                 + python3 + esmd_check.py  (опрос ESMD/EB500 по SCPI)        │
│  postgres       база данных (история 90 дней, тренды 365 дней)              │
│  zabbix-map     : 8081  карта Москвы и области, выгрузка в Excel            │
└──────────────────────────────────────────────────────────────────────────────┘
```

Все четыре компонента — Docker-контейнеры. Образы собраны заранее и лежат в комплекте (`images.tar`), поэтому интернет на объекте не нужен ни при установке, ни при работе.

### 1.2. Где работает сервер

Целевой компьютер — Windows 10 Корпоративная LTSC 2019 (сборка 17763). Docker Desktop на ней не работает: ему нужна Windows 10 22H2 (сборка 19045) или новее, а WSL2 — минимум сборка 18362. Поэтому есть два пути:

| Путь | Где | Когда выбирать |
|---|---|---|
| **A. Виртуальная машина Hyper-V** (основной) | Windows 10 Корпоративная LTSC (фото 2) | сервер на главном компьютере, как в ТЗ |
| **B. Docker Desktop** (запасной) | Windows 11 Pro (фото 1) или Windows 10 22H2+ | если путь A не заработал (например, виртуализация выключена в BIOS и включить нельзя) |

**Путь A.** В Hyper-V (входит в Windows 10 Корпоративная) запускается готовая виртуальная машина Debian 12. Внутри неё уже установлены Docker и весь стек. Виртуальная машина получает свой IP-адрес в локальной сети. Рабочие места, агенты и оборудование обращаются к **IP виртуальной машины**, а не к IP Windows.

**Путь B.** Docker Desktop ставится прямо на Windows 11. Контейнеры доступны по **IP самой Windows**.

### 1.3. Как собираются данные

- **Cisco**: сервер опрашивает маршрутизаторы по SNMPv3 (только чтение). Шаблон встроенный: `Cisco IOS by SNMP`.
- **Infinet R5000**: опрос по SNMP, шаблон `Infinet Wireless R5000 (SNMP, основа)`. Собирает состояние радиолинка, SNR, RSSI, скорость, повторы, температуру и интерфейсы.
- **ESMD и EB500**:
  - раз в 30 с проверяется ping, раз в минуту — открыт ли TCP-порт 5555;
  - раз в 5 минут скрипт `esmd_check.py` открывает одно соединение, отправляет SCPI-запросы (`*IDN?`, `SYSTem:ERRor?` и др.) и возвращает ответы, из которых получаются отдельные показатели.
- **ПК Windows**: на каждом ПК стоит агент Zabbix. Он отдаёт загрузку CPU, память, диски, службы. Шаблон `Windows by Zabbix agent`.
- **Триггеры**: недоступность, падение линка, низкий сигнал, ошибки прибора и т.п. Активные проблемы видны в веб-интерфейсе (панель «Проблемы») и цветом маркеров на карте. Почта, мессенджеры и звук не настраиваются — решение заказчика.
- **Хранение**: история 90 дней, тренды (средние за час) 365 дней. Каждую ночь в 03:00 делается резервная копия.

## 2. Подготовка дома (с интернетом)

### 2.1. Скачать комплекты

На GitHub: репозиторий `zabbix-config` → вкладка **Actions**.

1. Workflow **offline-bundle** → последний зелёный запуск → внизу **Artifacts** → `zabbix-offline` (~1,5 ГБ). Внутри:
   - `images.tar` — образы Docker;
   - `installers/` — Docker Desktop, WSL, агенты Zabbix для Windows (агент 2 для Win10/11, классический для Win7 x64/x86);
   - `map/data/moscow.pmtiles` — подложка карты;
   - скрипты, шаблоны, документация, `SHA256SUMS`.
2. Workflow **vm-image** → последний зелёный запуск → **Artifacts** → `zabbix-vm`. Внутри:
   - `zabbix-vm-debian12.zip` — диск виртуальной машины;
   - `SHA256SUMS`;
   - скрипты `hyperv-install.ps1`, `hyperv-create-vm.ps1`;
   - `HYPERV-VM.md`.

GitHub отдаёт артефакты как zip. Распакуйте их на компьютере, где скачивали.

### 2.2. Что есть в комплектах для «голой» Windows

| Что | Где | Для чего |
|---|---|---|
| Диск ВМ + скрипты Hyper-V | `zabbix-vm` | путь A; Hyper-V встроен в Windows 10 Корпоративная, ставить отдельно не нужно |
| Docker Desktop, WSL | `zabbix-offline/installers` | путь B (Windows 11) |
| Образы Docker, карта, скрипты | `zabbix-offline` | путь B (в ВМ всё уже внутри) |
| Агенты Zabbix (Win10/11, Win7 x64/x86) | `zabbix-offline/installers` | ПК Windows |
| Firefox ESR 153 (Win10/11) и ESR 115 (Win7 x64/x86), русские | `zabbix-offline/installers/browsers` | **обязательно:** на Windows 10 LTSC 2019 нет Edge, есть только IE11, а интерфейс Zabbix 7.0 и карта в IE не работают; на Win7 современные Chrome/Edge не ставятся |
| WinSCP portable | `zabbix-offline/installers/tools` | забрать бэкапы из ВМ (6.3) |

Распаковка zip на Windows без дополнительных программ: правой кнопкой → «Извлечь всё» или в PowerShell `Expand-Archive <файл>.zip -DestinationPath <папка>`.

Установка Firefox (тихо): `msiexec /i Firefox-ESR-win10-11-x64.msi /qn`.

### 2.3. Что ещё взять

- **Флешка** от 16 ГБ, файловая система **exFAT или NTFS** (FAT32 не подходит: в комплекте файлы больше 4 ГБ).
- MIB-файлы и PDF-руководства, если есть.
- Список устройств: имя, IP, тип, адрес или координаты (для карты), версия SNMP и учётные данные.
- Установочный ISO Windows 10 Корпоративная LTSC 2019 (на случай, если для включения Hyper-V потребуются исходные файлы, см. 3.2).
- Распечатку этого документа.

### 2.4. Проверить флешку

После копирования на флешку проверьте, что файлы не повреждены. В PowerShell:

```
Get-FileHash E:\zabbix-vm\zabbix-vm-debian12.zip -Algorithm SHA256
```

Сравните с соответствующей строкой в `SHA256SUMS`. Для `zabbix-offline` проверку делает скрипт установки.

## 3. Путь A: виртуальная машина Hyper-V на Windows 10 LTSC

Время: 30–60 минут, из них около 10 минут — первый запуск ВМ.

### 3.1. Проверка компьютера

**Лучше всего — заранее, до выезда, если есть доступ к главному компьютеру.** Скрипт ничего не меняет, только проверяет и пишет отчёт `precheck-<имя ПК>.txt`:

```
Set-ExecutionPolicy -Scope Process Bypass
.\precheck.ps1
```

(лежит в `zabbix-vm` и в `zabbix-offline\scripts`). Он проверяет выпуск и сборку Windows, наличие и состояние компонента Hyper-V, виртуализацию в BIOS, SLAT, память, диск, сеть, браузер, ssh, и пишет итог: возможен ли вариант A и что сделать. Если что-то не так — см. «Если Hyper-V недоступен» ниже.

Ручная проверка:

PowerShell **от имени администратора**:

```
systeminfo
```

В конце вывода раздел «Требования Hyper-V». Нужно «Да» во всех строках: расширения режима мониторинга виртуальной машины, виртуализация включена во встроенном ПО, преобразование адресов второго уровня (SLAT), предотвращение выполнения данных.

Если там написано «Обнаружена низкоуровневая оболочка…», Hyper-V уже включён — переходите к 3.3.

Если «Виртуализация включена во встроенном ПО: Нет»:
- перезагрузитесь в BIOS/UEFI;
- включите Intel Virtualization Technology (VT-x), в некоторых BIOS также VT-d;
- сохраните настройки.

У Pentium G3430 поддержка есть, нужно только включить. Если включить нельзя — переходите на путь B.

Ресурсы: ВМ получает 2 ядра и 5 ГБ памяти, Windows остаётся около 5 ГБ. Свободного места на диске нужно не меньше 15 ГБ.

### 3.2. Включить Hyper-V (один раз)

Скопируйте папку `zabbix-vm` с флешки, например в `D:\zabbix-vm`. Распакуйте `zabbix-vm-debian12.zip` в ту же папку (правой кнопкой → «Извлечь всё» или `Expand-Archive .\zabbix-vm-debian12.zip -DestinationPath .`): получится `zabbix-vm-debian12.vhdx`.

PowerShell от имени администратора:

```
cd D:\zabbix-vm
Set-ExecutionPolicy -Scope Process Bypass
.\hyperv-install.ps1
```

**Перезагрузите Windows.**

Отдельный установщик Hyper-V не нужен: это встроенный компонент Windows 10 Корпоративная, его файлы уже есть в системе, интернет не требуется. Если Windows всё же сообщит, что не найдены исходные файлы (бывает на урезанных сборках), подключите установочный ISO той же версии Windows 10 LTSC 2019 и укажите его: `.\hyperv-install.ps1 -Source E:\sources\sxs` (E: — буква ISO). **Возьмите этот ISO на флешку на всякий случай.**

Ручной способ без скрипта: «Панель управления → Программы → Включение или отключение компонентов Windows → Hyper-V» (отметить все подпункты) → перезагрузка.

### 3.3. Создать и запустить ВМ

```
cd D:\zabbix-vm
Set-ExecutionPolicy -Scope Process Bypass
.\hyperv-create-vm.ps1 -VhdxPath D:\zabbix-vm\zabbix-vm-debian12.vhdx
```

Что делает скрипт:
1. Показывает сетевые адаптеры. Введите имя того, который подключён к локальной сети (обычно `Ethernet`).
2. Создаёт внешний коммутатор `ZabbixExternal`. **Сеть Windows пропадёт на несколько секунд** — это нормально.
3. Копирует диск в `C:\Hyper-V\ZabbixVM\`, создаёт ВМ `ZabbixVM` (2 ядра, 5 ГБ, поколение 2, Secure Boot с шаблоном Microsoft UEFI CA).
4. Включает автозапуск ВМ вместе с Windows, запускает её и выводит IP-адрес.

Если ВМ не загружается (чёрный экран, ошибка загрузки): удалите ВМ в «Диспетчере Hyper-V» и повторите команду с параметром `-Generation 1`.

### 3.4. Первый вход в ВМ и сеть

Откройте консоль ВМ: «Диспетчер Hyper-V» → двойной щелчок по `ZabbixVM`, или команда `vmconnect localhost ZabbixVM`.

1. Логин `zbxadmin`, пароль `zbxadmin`. Система сразу попросит сменить пароль: введите старый, затем новый дважды. **Запишите новый пароль.**
2. Задайте постоянный IP-адрес:
   ```
   sudo zbx-netconfig
   ```
   Выберите «статический»: IP (например `192.168.1.50/24`), шлюз, DNS. Если в сети есть сервер времени, укажите его там же. Проверка: `ip -br a`.

   Постоянный адрес обязателен: на него будут настроены агенты, рабочие места и закладки браузеров.

### 3.5. Дождаться первого запуска

При первой загрузке ВМ сама:
- загружает образы Docker;
- создаёт базу со случайным паролем;
- запускает контейнеры;
- импортирует шаблоны, создаёт группы и устанавливает срок хранения 90 дней.

Это занимает **до 10 минут**, сайт в это время не открывается.

Ход выполнения:

```
journalctl -u zabbix-firstboot -f        # Ctrl+C — выйти из просмотра
systemctl status zabbix-firstboot        # «active (exited)» — готово
cd /opt/zabbix && sudo docker compose ps # все контейнеры «Up»
```

Если первый запуск завершился ошибкой: прочитайте `journalctl -u zabbix-firstboot`, устраните причину и выполните `sudo systemctl restart zabbix-firstboot`.

Дальше — раздел 5. Адрес сервера = **IP виртуальной машины**.

### 3.6. Если Hyper-V недоступен

| Причина | Вероятность | Что делать |
|---|---|---|
| Виртуализация выключена в BIOS/UEFI | **самая частая** | войти в BIOS (обычно Del или F2 при включении), включить Intel Virtualization Technology (VT-x), сохранить. Если BIOS под паролем — пароль нужен заранее у владельца компьютера/ИТ |
| Файлы компонента удалены из сборки Windows | редко | `hyperv-install.ps1 -Source E:\sources\sxs` с ISO той же версии Windows 10 LTSC 2019 |
| Выпуск без Hyper-V (Home) | исключено по фото: «Корпоративная LTSC» | — |
| Процессор без SLAT | исключено: у Pentium G3430 (Haswell) есть EPT | — |
| Старые VirtualBox/VMware мешают | редко | обновить или удалить их |
| Windows не активирована | не влияет на Hyper-V | — |

Если виртуализацию включить невозможно, ни Hyper-V, ни Docker Desktop (ему она тоже нужна) на этом компьютере не заработают. Запасной путь — **B на другом компьютере** с Windows 11 или Windows 10 22H2 и включённой виртуализацией (например, ПК с фото 1), который будет работать круглосуточно. Агенты и рабочие места тогда указывают на его IP. Сервер Zabbix под Windows без виртуализации не работает в принципе (у Zabbix нет сервера для Windows).

Поэтому главное для предотвращения: **до выезда запустить `precheck.ps1` на главном компьютере** или хотя бы узнать, есть ли пароль на BIOS и включена ли виртуализация («Диспетчер задач → Производительность → ЦП → Виртуализация: Включено»).

## 4. Путь B: Docker Desktop на Windows 11 (запасной)

Время: 30–40 минут.

1. Включите виртуализацию в BIOS, если она выключена (см. 3.1).
2. Скопируйте папку комплекта `zabbix-offline-<дата>` с флешки в `C:\zabbix`. Путь без пробелов и кириллицы.
3. PowerShell от имени администратора:
   ```
   cd C:\zabbix
   Set-ExecutionPolicy -Scope Process Bypass
   .\scripts\install-docker-win11.ps1
   ```
   Скрипт включает компоненты Windows, ставит WSL и Docker Desktop из папки `installers`. Интернет не нужен.
4. **Перезагрузите компьютер.**
5. Запустите Docker Desktop из меню «Пуск»:
   - примите лицензию;
   - вход в учётную запись Docker пропустите;
   - в Settings → General включите **Start Docker Desktop when you sign in**.
6. Снова PowerShell от администратора:
   ```
   cd C:\zabbix
   .\scripts\load-and-start.ps1
   ```
   При первом запуске откроется Блокнот с файлом `.env`:
   - замените `POSTGRES_PASSWORD=CHANGE_ME_LONG_RANDOM` на длинный пароль;
   - сохраните и закройте;
   - запустите скрипт ещё раз.

   Скрипт проверит контрольные суммы, загрузит образы и запустит контейнеры вместе с картой.
7. Через 1–2 минуты выполните первичную настройку:
   ```
   docker compose exec zabbix-server python3 /opt/zbx-tools/post_setup.py
   ```
8. Откройте порты в брандмауэре Windows:
   ```
   New-NetFirewallRule -DisplayName "Zabbix web" -Direction Inbound -Protocol TCP -LocalPort 80,8081 -Action Allow
   New-NetFirewallRule -DisplayName "Zabbix server" -Direction Inbound -Protocol TCP -LocalPort 10051 -Action Allow
   ```

**Ограничение пути B:** Docker Desktop запускается только после входа пользователя в Windows. Чтобы мониторинг восстанавливался сам после перезагрузки, настройте автоматический вход этого пользователя или держите сеанс открытым.

## 5. Настройка после установки (оба пути)

Далее `<IP>` — адрес сервера: IP виртуальной машины на пути A или IP Windows 11 на пути B.

### 5.1. Первый вход и пароли

1. С любого рабочего места откройте `http://<IP>/` в Firefox из комплекта (на главном компьютере с LTSC 2019 его нужно поставить первым делом).
2. Войдите как `Admin` / `zabbix`. **Сразу смените пароль:** User settings → Profile → Change password.
3. Впишите новый пароль в `.env` (`ZBX_API_PASSWORD=...`), иначе бэкап конфигурации и карта не смогут войти в API.
   - Путь A: `sudo nano /opt/zabbix/.env`, затем `cd /opt/zabbix && sudo docker compose up -d`.
   - Путь B: `notepad C:\zabbix\.env`, затем `docker compose -f docker-compose.yml -f docker-compose.map.yml up -d`.
4. Рекомендуется завести отдельного пользователя только для чтения (роль User) для карты и вписать его в `.env`. Подробнее в `MAPS.md`.
5. Язык интерфейса: User settings → Profile → Language → Русский.

### 5.2. Уведомления только на экране

User settings → Profile → вкладка **Messaging**:
- включите **Frontend messaging**;
- **Play sound** установите в «Never».

Новые проблемы будут всплывать в углу окна браузера.

Сделайте главной страницей **Dashboards** (Панели) — на ней есть виджет «Проблемы».

### 5.3. Время

**Путь A:**
- ВМ берёт время у Windows через службы интеграции Hyper-V, поэтому время на главном компьютере должно быть верным.
- Если в сети есть NTP-сервер, укажите его в `sudo zbx-netconfig`.
- Проверка: `timedatectl`, `chronyc sources`.

**Путь B:** контейнеры берут время Windows.

Если в сети есть NTP-сервер, настройте на него Windows:

```
w32tm /config /manualpeerlist:"<IP NTP>" /syncfromflags:manual /update
w32tm /resync
```

### 5.4. Добавление устройств

В интерфейсе: **Сбор данных → Узлы сети → Создать узел сети** (в англ. интерфейсе Data collection → Hosts → Create host).

Общее для всех устройств:
- **Имя узла** латиницей без пробелов, например `cisco-arbat`. **Видимое имя** — любое, по-русски.
- **Группы:** одна из «Регион/…» и одна из «Роль/…». Структура групп черновая и согласуется с заказчиком.
- **Вкладка «Инвентарь»** → «Вручную» → «Широта» и «Долгота» (например `55.7520` и `37.5960`). Тогда устройство появится на карте.

#### Cisco 1921 и 2901 (SNMPv3)

1. На маршрутизаторе выполните команды SNMPv3 из `CISCO.md`. Вместо `<ZBX_IP>` подставьте IP сервера.
2. В Zabbix:
   - **Интерфейсы** → Добавить → SNMP;
   - IP маршрутизатора, порт 161;
   - версия SNMPv3, Security name `zbxmon`, Security level `authPriv`;
   - Authentication protocol `SHA1`, Privacy protocol `AES128`, пароли как на маршрутизаторе.
3. **Шаблоны:** `Cisco IOS by SNMP`.
4. Проверка: через 5–10 минут в «Мониторинг → Последние данные» появятся значения, а значок SNMP у узла станет зелёным.

#### Infinet R5000

1. Включите SNMP-агент на устройстве (по умолчанию выключен) и задайте community (v2c) или пользователя (v3).
2. В Zabbix: интерфейс SNMP (IP устройства, порт 161, версия как на устройстве; для v2c community `{$SNMP_COMMUNITY}` и макрос на узле со значением community).
3. **Шаблон:** `Infinet Wireless R5000 (SNMP, основа)`.
4. Пороги (SNR, RSSI, температура и др.) — макросы `{$INFINET.*}` на вкладке «Макросы» узла. Значения по умолчанию предварительные, их нужно согласовать.

**Важно:** OID взяты из MIB WANFleX/MINT. На реальном R5000 они не проверялись. Если элементы получают статус «не поддерживается», снимите `snmpwalk` (см. `INFINET.md`) и пришлите для доработки шаблона.

#### R&S ESMD и EB500

1. Интерфейс: **Агент**, IP прибора. Порт не важен: агент на приборе не ставится, интерфейс нужен только для адреса.
2. **Шаблон:** `R&S ESMD (ICMP, TCP-порт)` или `R&S EB500 (ICMP, TCP, SCPI)`.
3. Порт SCPI по умолчанию 5555, меняется макросом `{$ESMD.PORT}` или `{$EB500.PORT}`.
4. Проверка вручную, с сервера:
   ```
   docker compose exec zabbix-server /usr/lib/zabbix/externalscripts/esmd_check.py json <IP прибора> 5555 '*IDN?' 'SYSTem:ERRor?'
   ```
   На пути A перед этим выполните `cd /opt/zabbix` и добавьте `sudo` в начало команды. Должен вернуться JSON с `"tcp": 1` и ответом на `*IDN?`.

Пока сервер опрашивает прибор (каждые 5 минут, доли секунды), ПО оператора (ESMD-Control) может кратко получить отказ в подключении, если прибор допускает только одно соединение. Если это мешает, увеличьте интервал мастер-элемента в шаблоне.

#### ПК Windows (агенты)

Установщики лежат в `installers/` комплекта `zabbix-offline`:

| ОС на ПК | Файл |
|---|---|
| Windows 10/11 x64 | `zabbix_agent2-7.0.32-windows-amd64-openssl.msi` |
| Windows 7 x64 | `zabbix_agent-7.0.32-windows-amd64-openssl.msi` |
| Windows 7 x86 | `zabbix_agent-7.0.32-windows-i386-openssl.msi` |

Установка на ПК (командная строка от администратора):

```
msiexec /i <файл>.msi /qn SERVER=<IP> SERVERACTIVE=<IP> HOSTNAME=<имя ПК>
netsh advfirewall firewall add rule name="Zabbix agent" dir=in action=allow protocol=TCP localport=10050
```

Можно ставить и через мастер (двойной щелчок по msi): в поле «Zabbix server IP/DNS» укажите `<IP>`.

В Zabbix: интерфейс «Агент» (IP ПК, порт 10050), шаблон `Windows by Zabbix agent`, имя узла = `HOSTNAME` из установки.

Классический агент 7.0 на Windows 7 официально поддерживается, но **проверьте на одном ПК**, прежде чем ставить на все.

### 5.5. Карта и Excel

- Карта: `http://<IP>:8081/`. Маркеры окрашены по самой серьёзной проблеме устройства (зелёный — норма, серый — недоступно). Щелчок по маркеру показывает проблемы и ссылку в Zabbix.
- Устройства без координат перечислены справа.
- **Экспорт в Excel** — кнопка вверху. Листы «Устройства» и «Проблемы».
- Нужен современный браузер (Chrome, Edge, Firefox). В старых браузерах Windows 7 карта может не работать; веб-интерфейс Zabbix 7.0 тоже требует современного браузера — проверьте на месте.
- Схемы связей (не географические) рисуются штатно: Мониторинг → Карты → Создать карту.

## 6. Эксплуатация

### 6.1. Перезагрузка и автозапуск

- **Путь A:**
  - ВМ запускается автоматически через 30 секунд после старта Windows, вход пользователя не нужен;
  - при выключении Windows ВМ корректно завершается;
  - внутри ВМ стек поднимается сам.
- **Путь B:** после входа пользователя запускается Docker Desktop, контейнеры поднимаются сами.

**Обязательная проверка при сдаче:** перезагрузите Windows и через 5 минут откройте веб-интерфейс.

### 6.2. Резервные копии

Создаются ежедневно в 03:00, хранятся 30 последних. В каждую копию входят дамп БД `zabbix-ГГГГММДД-ЧЧММ.dump` и выгрузка шаблонов и узлов `config-ДАТА/`.

- **Путь A:**
  - копии лежат в ВМ в `/opt/zabbix/backups`;
  - вручную: `sudo /opt/zabbix/scripts/backup.sh`;
  - расписание: `systemctl list-timers zabbix-backup.timer`.
- **Путь B:**
  - копии лежат в `C:\zabbix\backups`;
  - вручную: `.\scripts\backup.ps1`;
  - расписание (один раз):
    ```
    schtasks /Create /SC DAILY /ST 03:00 /TN ZabbixBackup /RU SYSTEM /TR "powershell -ExecutionPolicy Bypass -File C:\zabbix\scripts\backup.ps1"
    ```

Раз в неделю копируйте бэкапы на внешний носитель.

### 6.3. Забрать бэкап из ВМ на Windows (путь A)

```
scp -r zbxadmin@<IP ВМ>:/opt/zabbix/backups D:\ZabbixBackups
```

Если команды `scp` нет (на LTSC 2019 клиент OpenSSH может быть не установлен, а без интернета его не доставить), используйте WinSCP portable из `installers/tools` (распаковать zip, запустить WinSCP.exe): протокол SFTP, хост `<IP ВМ>`, пользователь `zbxadmin`, папка `/opt/zabbix/backups`.

### 6.4. Восстановление из бэкапа

**Путь A** (в ВМ, файл дампа в `/opt/zabbix/backups`):

```
cd /opt/zabbix
sudo docker compose stop zabbix-server zabbix-web
sudo docker compose exec -T postgres sh -c 'pg_restore -U $POSTGRES_USER -d $POSTGRES_DB --clean --if-exists /backups/zabbix-ГГГГММДД-ЧЧММ.dump'
sudo docker compose start zabbix-server zabbix-web
```

**Путь B:**

```
.\scripts\restore.ps1 backups\zabbix-ГГГГММДД-ЧЧММ.dump
```

Восстановление нужно проверить один раз при сдаче (критерий приёмки ТЗ): сделайте бэкап, добавьте тестовый узел, восстановите, убедитесь, что тестовый узел пропал.

### 6.5. Обновление

Версия Zabbix (7.0.32) закреплена и меняется только по решению заказчика. Порядок:

1. Дома собирается новый комплект.
2. На объекте делается бэкап.
3. Новый `images.tar` загружается: путь A — `sudo docker load -i` в ВМ, путь B — `load-and-start.ps1`.
4. Выполняется `docker compose up -d --no-build`.

Шаблоны после изменения переимпортируются командой `docker compose exec zabbix-server python3 /opt/zbx-tools/post_setup.py` (на пути A — в `/opt/zabbix` через `sudo`). Существующие узлы при этом не теряются.

## 7. Чек-лист приёмки

- [ ] Веб-интерфейс `http://<IP>/` открывается с рабочих мест; пароль Admin сменён.
- [ ] Cisco 1921 и 2901: SNMPv3 зелёный, есть графики интерфейсов.
- [ ] Infinet R5000: SNMP зелёный, элементы радиоканала получают данные (если нет — снять snmpwalk).
- [ ] ESMD и EB500: ping, порт 5555, «SCPI: отвечает» = 1, видна идентификация прибора.
- [ ] ПК Windows (включая Win7): агент зелёный, есть CPU/память/диски.
- [ ] Отключение тестового устройства от сети → через 1–3 минуты проблема в «Проблемах» и красный маркер на карте; после подключения проблема закрывается.
- [ ] Карта открывается, устройства с координатами на своих местах, Excel скачивается.
- [ ] Перезагрузка Windows → через 5 минут мониторинг работает сам.
- [ ] Бэкап создан, восстановление проверено.
- [ ] Время на сервере верное (`timedatectl` в ВМ или часы Windows).

## 8. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Сайт не открывается | Путь A: прошло ли 10 минут первого запуска (`systemctl status zabbix-firstboot`), верный ли IP ВМ (`ip -br a`). Путь B: запущен ли Docker Desktop, правила брандмауэра. Оба: `docker compose ps` — все ли контейнеры «Up» |
| «Zabbix server is not running» на сайте | `docker compose logs zabbix-server --tail 50`; обычно ждать минуту после запуска |
| Устройство SNMP «недоступно» | ping до устройства с сервера; ACL на Cisco разрешает IP сервера; совпадают версия SNMP, имя пользователя и пароли |
| ESMD/EB500 «порт недоступен» | прибор включён, порт 5555, не занят ли единственный сеанс другой программой |
| Агент Windows «недоступен» | служба «Zabbix Agent» запущена на ПК; правило брандмауэра 10050; в конфиге агента `Server=<IP>`; имя узла в Zabbix = Hostname агента |
| Карта без подложки (серый фон) | есть ли `map/data/moscow.pmtiles` (путь B) или `/opt/zabbix/map/data/` (путь A) |
| ВМ не грузится | пересоздать с `-Generation 1` (см. 3.3) |
| Неверное время в графиках | время Windows, часовой пояс `PHP_TZ=Europe/Moscow` в `.env` |
| Логи | `docker compose logs <сервис> --tail 100` (сервисы: postgres, zabbix-server, zabbix-web, zabbix-map) |

## 9. Что проверено и что нет

Проверено автоматически (GitHub Actions, на настоящем Zabbix 7.0.32):
- стек запускается из образов комплекта;
- первичная настройка проходит, шаблоны Infinet, ESMD и EB500 импортируются;
- опрос ESMD/EB500 через Zabbix на имитаторе прибора: зависимые элементы получают значения;
- работают карта и выгрузка Excel;
- работают экспорт конфигурации и `pg_dump`.

Образ ВМ проверяется загрузкой в QEMU/KVM — см. результат workflow **vm-image**.

**Не проверено** — проверить на месте:
- загрузка ВМ именно в Hyper-V на Windows 10 LTSC 2019;
- скрипты PowerShell на реальной Windows;
- установка Docker Desktop без интернета;
- опрос реальных Cisco, Infinet (OID), ESMD, EB500;
- агент на Windows 7;
- браузеры на Windows 7;
- восстановление из бэкапа;
- автозапуск после перезагрузки.
