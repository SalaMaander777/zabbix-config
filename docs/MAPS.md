# Карта Москвы и области со статусами устройств (ТЗ №7)

## Решение
Отдельный лёгкий сервис `zabbix-map` (вариант C из предварительного анализа), работает полностью офлайн.

- Бэкенд: Python (стандартная библиотека) + openpyxl, читает данные из Zabbix API (только методы `*.get`): узлы, инвентарь, интерфейсы, проблемы. Кэш 10 секунд.
- Фронтенд: Leaflet 1.9.4 + protomaps-leaflet 5.1.0 (лежат в `map/static/vendor/`, внешних запросов нет).
- Подложка: векторные тайлы OpenStreetMap (Protomaps, формат PMTiles), один файл `map/data/moscow.pmtiles` (Москва и область, до 13-го масштаба, около 170 МБ), отдаётся самим сервисом с поддержкой HTTP Range.
- Запуск отдельным файлом `docker-compose.map.yml`; основной `docker-compose.yml` не менялся.
- Схемы связей (не география) остаются штатными картами Zabbix: Мониторинг → Карты.

Возможности: цветной маркер по максимальной важности активной проблемы (цвета Zabbix; зелёный - в норме, серый - недоступен или отключён), всплывающая карточка с проблемами и ссылкой на узел в Zabbix, фильтр по группе, автообновление раз в 60 с, список узлов без координат, кнопка «Экспорт в Excel».

## Как задать координаты узла
Конфигурация → Узлы сети → узел → вкладка «Инвентарь» → режим «Вручную» → поля «Широта» и «Долгота» (десятичные градусы, например `55.7570` и `37.6150`; запятая тоже допустима). Узлы без координат или с неверными значениями показываются списком справа и в Excel без координат.

## Запуск и открытие
```
docker compose -f docker-compose.yml -f docker-compose.map.yml up -d
```
Карта: `http://<IP главного компьютера>:8081/` (порт задаёт `MAP_PORT` в `.env`, пример в `.env.example`). Установщик `scripts/load-and-start.ps1` поднимает карту автоматически, если рядом есть `docker-compose.map.yml`.

Настройки в `.env` (необязательные): `MAP_PORT` (по умолчанию 8081), `ZBX_FRONTEND_URL` (адрес веб-интерфейса Zabbix для ссылок, например `http://10.0.0.5:8080`; по умолчанию - тот же хост, порт 80), `ZBX_API_USER` / `ZBX_API_PASSWORD`.

Рекомендация: завести в Zabbix отдельного пользователя только на чтение (роль «User», доступ на чтение к нужным группам узлов) и указать его в `ZBX_API_USER` / `ZBX_API_PASSWORD`, а не использовать `Admin`. Пароль в браузер не передаётся. Порт 8081 карты не требует входа: открывайте его только во внутренней сети.

## Экспорт в Excel
Кнопка «Экспорт в Excel» (или `http://<IP>:8081/export.xlsx`). Листы: «Устройства» (имя, группы, IP, координаты, состояние, число проблем, максимальная важность и др.), «Проблемы» (узел, проблема, важность, начало, длительность), «Сведения».

## Тайлы: получение и обновление
Нужен интернет, делается на машине сборки (скрипт сборки комплекта вызывает это сам; при неудаче сборка продолжается без тайлов):
```
map/fetch-tiles.sh
```
Скрипт скачивает go-pmtiles (версия зафиксирована) и вырезает из дневной сборки build.protomaps.com область `35.1,54.2,40.3,56.98` до масштаба 13 (переменные `BBOX`, `MAXZOOM`, `PMTILES_VERSION`). Файл `map/data/moscow.pmtiles` в git не хранится. Обновить подложку = заменить файл (перезапуск не нужен). Без файла карта работает: серый фон и маркеры.

## Ограничения
- Нужен современный браузер (Chrome/Edge/Firefox последних лет). Windows 7 и старые браузеры не поддерживаются: подложка и интерфейс могут не работать; маркеры без подложки - вероятно, да, не проверялось.
- Подписи на карте рисуются системными шрифтами браузера.
- Проблемы привязываются к узлу через триггер; проблемы отключённых узлов не показываются, подавленные не учитываются в цвете.

## Что не проверено
- Работа на реальном Zabbix с обычным пользователем «только чтение» (проверено на тестовом стенде-моке и в CI на настоящем Zabbix).
- Windows 7, Internet Explorer, старые Edge/Chrome.
- Нагрузка более ~1000 узлов (рассчитано на ~100).
- Обновление тайлов на объекте без интернета: только заменой файла.

Ответы карты содержат заголовки `X-Frame-Options: DENY` и `Referrer-Policy: no-referrer`. Карта работает только на чтение (разрешены лишь методы Zabbix API `*.get`).
